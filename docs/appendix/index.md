# 부록 🧰

랩 본문에 넣지 않은 것을 모았습니다. **어느 것도 랩 진행에 필요하지 않습니다.** 시간이 남을 때, 또는 나중에 혼자 해볼 몫입니다.

랩에 붙여 두지 않고 따로 모은 이유는 **어디에 끼울지를 그날 정하기 위해서**입니다. 앞선 랩을 끝냈다면 순서에 상관없이 골라 하면 됩니다.

부록은 성격이 둘로 갈립니다. **그날 무엇이 부족한지 보고 고르면 됩니다.**

### 제품을 더 만져 본다

랩에서 하지 않은 조작을 해 봅니다. 진도가 빠르고 손이 남을 때 꺼냅니다.

| 부록 | 분 | 먼저 해야 하는 것 | 무엇을 보나 |
|---|---|---|---|
| [내 에이전트를 Copilot Studio로 가져가기](./to-copilot-studio.html) | 10 | [Lab 1](../lab1.html) | 같은 에이전트가 도구를 바꾸면 무엇이 달라지는가 |
| [에이전트가 에이전트를 부른다](./connected-agent.html) | 30 | [Lab 2](../lab2.html)·[Lab 3](../lab3.html)·[Lab 6](../lab6.html) | 두 에이전트를 도구처럼 부르고, 설명 하나로 경로를 바꾸기 |

### 왜 그런지 이해한다

조작보다 **판단**을 다룹니다. 다른 도구로 옮겨 가도 남는 이야기라, 수준이 높은 차수에서 값이 큽니다.

| 부록 | 분 | 먼저 해야 하는 것 | 무엇을 보나 |
|---|---|---|---|
| [에이전트 안에서 일어나는 일](./inside-the-agent.html) | 5+10+10 | [Lab 2](../lab2.html) | RAG·인덱싱 · 토큰과 비용 · 문서가 답을 정한다 |
| [지침을 어떻게 쓰는가 — 마크다운과 구조](./instructions-markdown.html) | 15 | [Lab 2](../lab2.html) | 지침이 왜 그런 모양이었나. 근거가 있는 말과 없는 말 |
| [모델을 바꾸면 같은 지침이 다르게 지켜진다](./model.html) | 20 | [Lab 2](../lab2.html) | 지침은 같은데 답이 갈린다. 근거 표시가 거짓인 경우 |
| [읽어 오는 양 — 1,000행짜리 표를 붙이면](./read-volume.html) | 20 | [Lab 5](../lab5.html) | 전부 오지 않는다. 그런데 그 사실이 안 드러난다 |

{: .note }
**뒤쪽 넷은 Copilot Studio를 안 쓰게 되더라도 남습니다.** 근거를 어디서 찾을지, 지침을 어떻게 쓸지, 모델이 무엇을 정하는지는 도구가 바뀌어도 같은 질문입니다.

{: .note }
**「에이전트 안에서 일어나는 일」은 세 부분이 따로 놉니다.** 1부(RAG·인덱싱)는 [Lab 2](../lab2.html) 17번의 **인덱싱 대기 시간에 읽는 자리**라 추가 시간이 들지 않습니다. 2부(토큰·비용)는 토크나이저를 직접 돌려 보는 15분 실습이고, 3부(문서 준비)는 10분이면 읽습니다. 셋을 따로 꺼내 써도 됩니다.

{: .warning }
**「지침을 어떻게 쓰는가」·「모델을 바꾸면」·「읽어 오는 양」은 끝나고 반드시 되돌려 놓으세요.** 모델과 지침을 바꾼 채로 두면 이어지는 랩이 다른 조건에서 돌아갑니다. 되돌릴 지침 원문은 각 랩의 「여기까지의 지침」에 있습니다.
