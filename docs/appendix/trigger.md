약 25분.

> **이 부록에서 하는 것**: Forms로 제출한 경조사 신청을 트리거로 받아, 에이전트가 목록에 기록하게 합니다.
>
> **완성 신호**: 양식을 제출하면 활동에 트리거 실행이 완료됨으로 남고 목록에 한 줄이 추가된다

---

## 준비

- `경조 신청 기록` 도구(SharePoint 항목 만들기)와 `경조신청_HGD` 목록이 있는 복리후생 안내 도우미에서 합니다.

---

## 단계 ① 양식과 트리거 추가

1. [경조사 신청 양식 템플릿]({{ site.tdg.forms_template_url }})을 열고 오른쪽 위 **복제**를 누릅니다.

    ![복제 버튼이 있는 양식 템플릿](../../assets/appendix/trigger/1.png)

2. 복제한 양식의 제목을 아래로 바꾸고 문항 셋을 확인합니다. `HGD` 대신 본인 이니셜을 넣습니다.

    ```
    경조사 신청 (HGD)
    ```

    | 문항 | 형식 |
    |---|---|
    | 경조 신청 사유를 입력하세요. | 긴 텍스트 |
    | 신청자 이름을 입력하세요 | 짧은 텍스트 |
    | 경조 날짜를 입력하세요 | 날짜 |

    ![제목을 바꾼 복제 양식과 문항 셋](../../assets/appendix/trigger/2.png)

3. 개요의 **트리거**에서 **+ 트리거 추가**를 누르고, Microsoft Forms의 **새 응답이 제출되는 경우**를 고른 뒤 **다음**을 누릅니다.

    ![개요의 트리거 추가 버튼](../../assets/appendix/trigger/3.png)

    ![트리거 목록의 새 응답이 제출되는 경우](../../assets/appendix/trigger/3-2.png)

4. **로그인**의 Microsoft Copilot Studio와 Microsoft Forms에 초록 확인 표시가 있는지 봅니다. 표시가 없으면 **⋯**에서 연결을 새로 만든 뒤 **다음**을 누릅니다.

    ![로그인의 두 연결과 다음 버튼](../../assets/appendix/trigger/4.png)

5. **양식 ID**에서 2번에서 이름을 바꾼 양식을 고릅니다.

    ![양식 ID 목록에서 본인 양식 선택](../../assets/appendix/trigger/5.png)

    **이 트리거에 의해 호출될 때 에이전트에 대한 추가 지침** 칸의 `Use content from 본문` 줄 아래에 아래를 붙여넣고 **트리거 생성**을 누릅니다.

    ```
    [경조사 신청 처리]
    Forms로 들어온 경조사 신청 한 건을 처리한다.
    전달된 내용에는 [신청자] [경조 날짜] [경조 신청 사유] 세 값이 들어 있다.
    경조 신청 사유를 읽고 사유를 판단한다. 사유는 아래 여섯 가지 중 하나로만 적는다.
    본인 결혼 / 자녀 결혼 / 배우자 출산 / 본인·배우자 부모상 / 조부모·형제자매상 / 규정 없음
    경조금과 경조휴가는 경조사·생활지원 문서의 표에 적힌 값을 쓴다. 규정 없음이면 둘 다 0으로 적는다.
    경조 신청 기록 도구로 한 항목을 추가한다. 열에는 아래 값을 넣는다.
    제목: 신청자와 사유
    신청자: [신청자] 값 그대로
    원문: [경조 신청 사유] 값 그대로
    사유: 위에서 판단한 사유
    발생일: [경조 날짜] 값을 yyyy-MM-dd 형식으로
    경조금: 원 단위 숫자만
    경조휴가: 일 단위 숫자만
    근거: 문서 이름
    ```

    {: .warning }
    **`Use content from 본문` 줄은 지우지 않습니다.** 10번에서 이 칩을 응답 내용으로 바꿉니다.

    ![양식 ID와 추가 지침을 채운 트리거 추가 창](../../assets/appendix/trigger/5-2.png)

    이 지침은 에이전트 지침에 넣지 않고 트리거에 저장합니다. 에이전트 지침은 대화 응답을 전제로 쓴 문장이라, 두 지시를 한곳에 두면 충돌할 수 있습니다.[^trigger]

## 단계 ② 트리거 흐름 수정

6. 개요의 **트리거**에서 방금 만든 **새 응답이 제출되는 경우** 이름을 누릅니다. Power Automate 디자이너가 열립니다.

    ![개요 트리거의 새 응답이 제출되는 경우](../../assets/appendix/trigger/6.png)

    트리거는 어느 응답이 들어왔는지만 넘깁니다. 7~10번에서 응답 내용을 가져와 에이전트에 넘기도록 흐름을 고칩니다.[^ecl]

7. `새 응답이 제출되는 경우`와 `Sends a prompt to the specified copilot for processing` 사이의 **+** 를 누르고 **작업 추가**를 고릅니다.

    ![두 노드 사이의 더하기 버튼](../../assets/appendix/trigger/7.png)

    검색 칸에 `forms`를 입력하고 **Microsoft Forms**의 **응답 세부 정보 가져오기**를 고릅니다.

    ![작업 추가의 응답 세부 정보 가져오기](../../assets/appendix/trigger/7-2.png)

    **양식 ID**에서 2번에서 이름을 바꾼 본인 양식을 고릅니다.

    ![양식 ID 목록의 본인 양식](../../assets/appendix/trigger/7-3.png)

    **응답 ID** 칸에 `/`를 입력하고 **동적 콘텐츠 삽입**을 고릅니다.

    ![응답 ID 칸의 동적 콘텐츠 삽입](../../assets/appendix/trigger/7-4.png)

    **새 응답이 제출되는 경우** 아래의 **응답 알림 목록 응답 ID**를 고릅니다. 노드가 **For each** 안으로 들어갑니다.

    ![동적 콘텐츠의 응답 알림 목록 응답 ID](../../assets/appendix/trigger/7-5.png)

8. `새 응답이 제출되는 경우`와 **For each** 사이의 **+** 를 누르고 **작업 추가**를 고릅니다.

    ![트리거와 For each 사이의 더하기 버튼](../../assets/appendix/trigger/8.png)

    검색 칸에 `변수`를 입력하고 **변수 초기화**를 고릅니다.

    ![변수 작업의 변수 초기화](../../assets/appendix/trigger/8-2.png)

    **이름**에 `myBody`를 입력하고 **유형**은 **문자열**을 고릅니다. **값**은 비워 둡니다.

    ```
    myBody
    ```

    {: .warning }
    **변수 초기화는 For each 안에 넣을 수 없습니다.** For each보다 위에 둡니다.

    ![이름 myBody와 유형 문자열](../../assets/appendix/trigger/8-3.png)

9. **For each** 안의 `응답 세부 정보 가져오기` 아래 **+** 를 누르고 **작업 추가**를 고릅니다.

    ![For each 안의 더하기 버튼](../../assets/appendix/trigger/9.png)

    검색 칸에 `변수`를 입력하고 **변수 설정**을 고릅니다.

    ![변수 작업의 변수 설정](../../assets/appendix/trigger/9-2.png)

    **이름**에서 `myBody`를 고르고, **값**에 아래 글자와 동적 콘텐츠를 순서대로 넣습니다. 동적 콘텐츠는 `/`를 입력하고 **동적 콘텐츠 삽입**에서 `응답 세부 정보 가져오기` 아래의 문항을 고릅니다.

    | 넣는 순서 | 무엇을 |
    |---|---|
    | 1 | 글자 `[신청자]: ` |
    | 2 | 동적 콘텐츠 `신청자 이름을 입력하세요` |
    | 3 | 글자 `, [경조 날짜]: ` |
    | 4 | 동적 콘텐츠 `경조 날짜를 입력하세요` |
    | 5 | 글자 `, [경조 신청 사유]: ` |
    | 6 | 동적 콘텐츠 `경조 신청 사유를 입력하세요.` |

    ![값에 글자와 동적 콘텐츠 셋을 넣은 변수 설정](../../assets/appendix/trigger/9-3.png)

10. `Sends a prompt to the specified copilot for processing` 노드를 누릅니다. **에이전트**가 본인 에이전트인지 확인합니다.

    **메시지** 칸 첫 줄 `Use content from` 뒤의 `본문` 칩을 **×** 로 지우고, 그 자리에 `/` › **동적 콘텐츠 삽입**으로 `myBody` 변수를 넣습니다. 아래 지침 줄은 그대로 둡니다.

    ![메시지 칸의 본문 칩을 myBody로 바꾼 화면](../../assets/appendix/trigger/10.png)

11. 디자이너 위쪽의 **초안 저장**을 누르고, 저장이 끝나면 **게시**를 누릅니다.

    {: .warning }
    **흐름을 게시해야 고친 흐름으로 트리거가 실행됩니다.** 초안 저장만 하면 이전 흐름이 돕니다.[^ecl]

    ![초안 저장과 게시 버튼](../../assets/appendix/trigger/11.png)

## 단계 ③ 게시와 제출 확인

12. Copilot Studio 탭으로 돌아가 에이전트 우측 상단 **게시**를 누릅니다. **최신 버전 강제 적용**은 체크하지 않고 **게시**합니다.

    ![작성자 자격 증명 트리거 검토 항목이 뜬 게시 창](../../assets/appendix/trigger/12.png)

    트리거는 게시한 에이전트에서 실행됩니다. 트리거로 실행될 때마다 Copilot 크레딧이 소비될 수 있습니다.[^billing]

13. Forms 탭에서 2번 양식 편집 화면의 **미리 보기**를 누릅니다.

    ![양식 편집 화면의 미리 보기 버튼](../../assets/appendix/trigger/13.png)

    신청자 이름에는 본인 이름, 경조 날짜에는 오늘 날짜를 넣고, 경조 신청 사유에 아래를 적은 뒤 **제출**을 누릅니다.

    ```
    외할머니께서 돌아가셨습니다
    ```

    ![세 문항을 채운 미리 보기와 제출 버튼](../../assets/appendix/trigger/13-2.png)

14. Copilot Studio 탭으로 돌아가 상단 탭 묶음(`+8` 등)에서 **활동**을 엽니다. 방금 실행된 트리거를 열어 상태가 **완료됨**인지 봅니다.

    ![탭 묶음의 활동](../../assets/appendix/trigger/14.png)

15. 같은 실행에서 `경조 신청 기록`이 호출되었는지, 기록 도구의 입력에 어떤 값이 들어갔는지 봅니다.

16. SharePoint 탭에서 `경조신청_HGD`를 새로 고칩니다.

17. 경조 신청 사유를 아래로 바꿔 13~16번을 한 번 더 합니다.

    ```
    처남이 결혼합니다
    ```

    **관찰**: 사유가 `규정 없음`, 경조금과 경조휴가가 `0`으로 기록된다.

    경조사·생활지원 문서의 표에서 결혼 항목은 본인과 자녀뿐입니다.

## 확인

**필수**: 여기까지 되면 이 부록은 통과입니다

- ① 트리거 흐름을 고쳐 게시하고 에이전트를 게시했다 (6~12번)
- ② 양식 제출로 경조사 신청 한 줄이 목록에 기록되었다 (13~16번)
{: .checklist }

**관찰**: 나오면 좋고, 안 나와도 실패가 아닙니다

- ③ 규정에 없는 신청이 규정 없음 · 0으로 기록되는가 (17번)
{: .checklist }
