> **이번 랩 완성물**: 항목과 수량을 받아 확인 카드로 확정받고 흐름을 부르는 [토픽](./glossary.html#topic)

50분 타이머. 3단(토픽 → 질문과 변수 → 확인 카드)으로 나눠 진행합니다.

## 단계 ① 자기계발비 신청 토픽

1. 상단 **토픽** 탭을 누릅니다. 창이 좁아 탭이 접혀 있으면 **+** 숫자 목록에서 **토픽**을 고릅니다.

    ![접힌 탭 목록의 토픽](../assets/tdg3/1.png)

    **+ 토픽 추가**를 누르고 **새로 시작**을 고릅니다.

    ![토픽 탭의 토픽 추가](../assets/tdg3/1-2.png)

2. 좌측 상단의 토픽 이름을 아래로 바꿉니다. 토픽 이름에는 이니셜을 붙이지 않습니다.

    ```
    자기계발비 신청
    ```

    ![토픽 이름을 바꾼 화면](../assets/tdg3/2.png)

3. **트리거** 노드의 **「토픽이 수행하는 작업 설명」** 칸에 아래를 입력합니다.

    ```
    자기계발비 신청을 접수한다. 자기계발비를 신청하겠다는 요청에 사용한다.
    ```

    **트리거 문구를 나열하는 칸이 없습니다.** 이 토픽이 언제 불릴지는 이 설명문으로 정해집니다.

    ![트리거 노드의 토픽이 수행하는 작업 설명](../assets/tdg3/3.png)

4. 트리거 노드 아래 **+** 를 누르고 **메시지 보내기**를 고릅니다.

    ![트리거 노드 아래의 +](../assets/tdg3/4.png)

    메시지 칸에 아래를 입력하고 우측 상단 **저장**을 누릅니다.

    ```
    자기계발비 신청 토픽이 시작되었습니다.
    ```

    ![메시지 노드를 넣은 토픽](../assets/tdg3/4-2.png)

5. 상단 **개요** 탭에서 **지침**의 **편집**을 누릅니다.

    맨 아래의 블록을 통째로 지웁니다. 아래 열두 줄이 모두 없어져야 합니다.

    ```
    [자기계발비 신청 처리]
    - 사용자가 자기계발비 신청을 요청하면 항목명과 수량을 확인한다. 둘 중 빠진 것이 있으면 먼저 되묻는다.
    - 지원단가는 /지원단가 조회 도구로 조회한다.
    - 금액은 지원단가 곱하기 수량으로 계산한다.
    - 처리 결과는 아래 형식으로 통보한다.

      [자기계발비 신청 접수]
      항목: 항목명
      지원단가: 지원단가원 곱하기 수량건
      금액: 금액원
      상태: 접수
    ```

    {: .warning }
    **이 블록이 남아 있으면 토픽이 불리지 않습니다.** 블록의 「빠진 것이 있으면 먼저 되묻는다」에 따라 에이전트가 항목명과 수량을 직접 되묻습니다.

    「답변 원칙」의 마지막 두 줄을 지웁니다.

    ```
    - 자기계발비 신청 시 이메일은 /System.User.Email 을 입력 변수로 넣는다.
    - 자기계발비 신청은 /자기계발비 신청 처리 HGD 흐름으로 처리한다.
    ```

    지운 자리에 아래 한 줄을 넣습니다. `/자기계발비 신청` 부분은 글자를 지우고 **`/`** 를 입력해 목록에서 토픽을 고릅니다. 칩으로 바뀐 뒤 **저장**을 누릅니다.

    ```
    - 자기계발비 신청은 /자기계발비 신청 토픽으로 수행한다.
    ```

    ![자기계발비 신청 토픽 칩이 들어간 지침](../assets/tdg3/5.png)

6. **새 테스트 세션**에서 신청합니다.

    ```
    자기계발비 신청하고 싶어요
    ```

    토픽의 메시지 `자기계발비 신청 토픽이 시작되었습니다.`가 먼저 나옵니다.

    ![토픽 메시지가 나온 테스트 창](../assets/tdg3/6.png)

    **새 테스트 세션**에서 한도를 물어봅니다.

    ```
    자기계발비는 1년에 얼마까지 지원돼?
    ```

    트리거 설명에는 신청 접수만 적었으므로 한도 질문에는 지식이 답합니다.

    ![지식 문서를 근거로 한 한도 답변](../assets/tdg3/6-2.png)

7. **새 테스트 세션**에서 항목을 넣어 신청합니다.

    ```
    도서구입으로 자기계발비 신청할게요
    ```

    항목을 함께 말해도 토픽의 메시지 `자기계발비 신청 토픽이 시작되었습니다.`가 나옵니다.

    ![항목을 함께 말한 신청에 나온 토픽 메시지](../assets/tdg3/7.png)

## 단계 ② 질문 노드와 변수

8. 상단 **토픽** 탭에서 `자기계발비 신청` 토픽을 엽니다.

    ![토픽 목록의 자기계발비 신청](../assets/tdg3/8.png)

    트리거 아래의 **메시지** 노드에서 **⋯** 를 누르고 **삭제**를 고릅니다.

    ![메시지 노드 메뉴의 삭제](../assets/tdg3/8-2.png)

    트리거 아래 **+** 를 누르고 **질문하기**를 고릅니다.

    ![노드 추가 메뉴의 질문하기](../assets/tdg3/8-3.png)

    질문 문구에 아래를 입력합니다.

    ```
    어떤 항목을 신청하시나요?
    ```

    ![질문 문구를 입력한 질문 노드](../assets/tdg3/8-4.png)

9. **식별** 항목을 **다중 선택 옵션**으로 바꿉니다.

    **사용자에 대한 옵션**의 **+ 새 옵션**을 눌러 선택지 다섯 개를 하나씩 넣습니다.

    ![사용자에 대한 옵션의 새 옵션](../assets/tdg3/9.png)

    ```
    도서구입
    온라인 강의
    어학시험 응시료
    자격증 응시료
    외부 세미나
    ```

    선택지는 `지원기준` 표의 항목명과 글자가 같아야 합니다. 자기계발비 신청 처리 흐름의 필터 쿼리가 이 값으로 행을 찾습니다.

    ![선택지 다섯 개를 넣은 질문 노드](../assets/tdg3/9-2.png)

10. 캔버스를 아래로 내려 선택지마다 자동으로 생긴 조건 갈래를 지웁니다. 갈래마다 **⋯** 를 누르고 **삭제**를 고릅니다.

    ![선택지마다 생긴 조건 갈래의 ⋯](../assets/tdg3/10.png)

11. **다음 이름으로 사용자 응답 저장** 칸의 `Var1`을 눌러 **변수 속성** 창을 엽니다.

    ![변수 속성 창의 변수 이름](../assets/tdg3/11.png)

    **변수 이름**을 아래로 바꾸고, **사용량**의 **다른 토픽에서 값 수신**을 체크합니다.

    ```
    항목명
    ```

    ![변수 이름 항목명과 다른 토픽에서 값 수신](../assets/tdg3/11-2.png)

12. 「어떤 항목을 신청하시나요?」 질문 노드 아래 **+** 를 누르고 **질문하기**를 고릅니다.

    ![항목명 질문 노드 아래의 +](../assets/tdg3/12.png)

    질문 문구에 아래를 입력합니다.

    ```
    몇 건 신청하시나요?
    ```

    ![질문 문구를 입력한 두 번째 질문 노드](../assets/tdg3/12-2.png)

    **식별**을 눌러 **식별할 정보 선택** 창을 엽니다. 검색 칸에 `숫자`를 입력하고 **숫자**를 고릅니다.

    ![식별할 정보 선택의 숫자](../assets/tdg3/12-3.png)

    **다음 이름으로 사용자 응답 저장** 칸의 `Var1`을 눌러 **변수 속성** 창을 엽니다. **변수 이름**을 아래로 바꾸고, **사용량**의 **다른 토픽에서 값 수신**을 체크합니다.

    ```
    수량
    ```

    ![변수 이름 수량과 다른 토픽에서 값 수신](../assets/tdg3/12-4.png)

13. 「몇 건 신청하시나요?」 질문 노드 아래 **+** 를 누르고 **메시지 보내기**를 고릅니다.

    ![수량 질문 노드 아래의 +](../assets/tdg3/13.png)

    메시지 칸에 아래를 붙여넣고 우측 상단 **저장**을 누릅니다.

    ```

    ```

    {: .warning }
    `Topic.` 을 빼고 `{항목명}` 만 적으면 글자로 들어갑니다. 붙여넣은 뒤 두 변수가 칩으로 바뀌었는지 확인합니다.

    ![항목명 칩이 들어간 메시지 노드](../assets/tdg3/13-3.png)

    켜 두면 오케스트레이터가 토픽 대신 흐름을 직접 불러, 질문과 확인 없이 기록합니다.

    ![자기계발비 신청 처리 흐름의 사용 설정됨 끄기](../assets/tdg3/14.png)

    ```

    항목을 물으면 `도서구입`, 수량을 물으면 `3`으로 답합니다. 두 질문 뒤에 확인 메시지가 나옵니다.

    ![항목과 수량 질문에 답한 뒤 나온 확인 메시지](../assets/tdg3/15.png)

16. 상단 **토픽** 탭에서 `자기계발비 신청` 토픽을 엽니다. 트리거 노드의 설명 끝에서 줄을 바꿔 아래를 더하고 우측 상단 **저장**을 누릅니다.

    ```
    항목과 수량을 받아 확인을 거친 뒤 신청내역에 기록한다. 항목명은 "도서구입", "온라인 강의", "어학시험 응시료", "자격증 응시료", "외부 세미나" 중 하나로 처리한다.
    ```

    질문 노드는 변수가 비어 있을 때만 묻습니다. 변수의 값 수신을 켜 두고 설명에 값의 목록을 적어야 오케스트레이터가 값을 미리 채웁니다.

    ![항목과 수량 문장을 더한 트리거 설명](../assets/tdg3/16.png)

17. **새 테스트 세션**에서 항목과 수량을 함께 말해 신청합니다.

    ```

    항목과 수량 질문 없이 확인 메시지가 나옵니다.

    ![질문 없이 바로 나온 확인 메시지](../assets/tdg3/17.png)

## 단계 ③ 확인 카드와 조건

18. 「건을 확인합니다.」 메시지 노드 아래 **+** 를 누르고 **적응형 카드로 질문**을 고릅니다.

    ![확인 메시지 노드 아래의 +](../assets/tdg3/18.png)

    오른쪽 **적응형 카드 노드 속성**에서 **적응형 카드 편집**을 누릅니다.

    ![적응형 카드 노드 속성의 적응형 카드 편집](../assets/tdg3/18-2.png)

    **카드 페이로드 편집기**의 내용을 지우고 아래를 붙여넣은 뒤 오른쪽 위 **Save**를 누릅니다.

    ```json
    {
      "type": "AdaptiveCard",
      "version": "1.5",
      "body": [
        { "type": "TextBlock", "text": "자기계발비 신청 확인", "weight": "Bolder", "size": "Medium" },
        { "type": "FactSet", "facts": [
          { "title": "항목", "value": "${항목명}" },
          { "title": "수량", "value": "${수량}" }
        ]}
      ],
      "actions": [
        { "type": "Action.Submit", "title": "확정", "data": { "actionSubmitId": "확정" } },
        { "type": "Action.Submit", "title": "취소", "data": { "actionSubmitId": "취소" } }
      ]
    }
    ```

    ![카드 페이로드를 붙여넣은 Adaptive card designer](../assets/tdg3/18-3.png)

19. 노드 속성의 **형식**을 **JSON 카드**에서 **수식 카드**로 바꿉니다.

    ![형식의 JSON 카드](../assets/tdg3/19.png)

    `facts` 안의 값 두 줄을 아래처럼 고쳐 씁니다.

    ```
    { title: "항목", value: Text(Topic.항목명) },
    { title: "수량", value: Text(Topic.수량) }
    ```

    {: .warning }
    **여기에는 `{x}` 버튼이 없습니다.** `Topic.` 접두사를 붙여 이름을 직접 씁니다. `항목명`은 `choice`, `수량`은 숫자라서 둘 다 `Text()` 로 감쌉니다.

    카드 노드 아래 **출력**에 `actionSubmitId`(string)가 있는지 보고 우측 상단 **저장**을 누릅니다. 카드의 버튼 `data`에 적은 `actionSubmitId`가 출력 변수로 자동으로 만들어지고, 누른 버튼의 값이 여기에 담깁니다.[^card]

    ![수식 카드로 고친 facts와 출력 actionSubmitId](../assets/tdg3/19-2.png)

20. 카드 노드 아래 **+** 를 누르고 **조건 추가**를 고릅니다.

    ![적응형 카드 노드 아래의 +](../assets/tdg3/20.png)

    **조건** 갈래와 **기타 모든 조건** 갈래가 생깁니다. **조건**의 **변수 선택**을 눌러 **사용자 지정** 탭에서 `actionSubmitId`를 고릅니다.

    ![변수 선택의 actionSubmitId](../assets/tdg3/20-2.png)

    비교는 **다음과 같음**으로 두고, 값 칸에 아래를 입력합니다.

    ```
    확정
    ```

    ![actionSubmitId 다음과 같음 확정](../assets/tdg3/20-3.png)

21. **조건** 갈래 아래의 **+** 를 누릅니다.

    ![조건 갈래 아래의 +](../assets/tdg3/21.png)

    **도구 추가**를 가리키고, **기본 도구** 탭의 목록에서 `자기계발비 신청 처리 HGD`를 고릅니다.

    ![도구 추가 기본 도구 탭의 자기계발비 신청 처리 흐름](../assets/tdg3/21-2.png)

    **작업** 노드의 **Power Automate 입력** 세 칸을 채웁니다. 칸 오른쪽 **⋯** 를 눌러 변수나 수식을 고릅니다.

    | 입력 | 값 |
    |---|---|
    | 항목명 | 수식 `Text(Topic.항목명)` |
    | 수량 | 변수 `수량` |
    | 이메일 | 시스템 변수 `User.Email` |

    ![입력 세 칸을 채운 작업 노드와 출력 결과](../assets/tdg3/21-3.png)

22. **작업** 노드 아래 **+** 를 누릅니다.

    ![작업 노드 아래의 +](../assets/tdg3/22.png)

    **메시지 보내기**를 고릅니다.

    ![노드 추가 메뉴의 메시지 보내기](../assets/tdg3/22-2.png)

    메시지 칸 도구 모음의 **`{x}`** 를 누릅니다.

    ![메시지 노드 도구 모음의 {x}](../assets/tdg3/22-3.png)

    `결과`를 고릅니다. `결과`는 흐름 노드 아래 **출력**에 자동으로 만들어진 변수이고, 흐름의 응답 노드에 정의한 출력이 그대로 들어옵니다.

    ![결과 변수를 넣은 메시지 노드](../assets/tdg3/22-4.png)

23. **기타 모든 조건** 갈래 아래의 **+** 를 누르고 **메시지 보내기**를 고릅니다.

    ![기타 모든 조건 아래의 +](../assets/tdg3/23.png)

    메시지 칸에 아래를 입력합니다.

    ```
    신청을 취소했습니다. 기록하지 않았습니다.
    ```

    ![취소 문구를 입력한 메시지 노드](../assets/tdg3/23-2.png)

24. 두 갈래가 다시 만나는 아래쪽 **+** 를 누르고 **토픽 관리** › **모든 토픽 종료**를 고릅니다.

    ![합류 지점의 + 와 토픽 관리 › 모든 토픽 종료](../assets/tdg3/24.png)

    확정과 취소 어느 갈래로 가도 이 노드를 지납니다. 우측 상단 **저장**을 누릅니다.

    {: .warning }
    **모든 토픽 종료가 없으면 토픽이 끝난 뒤 오케스트레이터가 토픽을 다시 부릅니다.** 방금 누른 버튼 값이 항목명에 들어가 수량을 다시 묻습니다. 이 노드가 오케스트레이터가 계획한 나머지 단계를 취소합니다.[^endall]

    ![두 갈래 아래에 붙은 모든 토픽 종료](../assets/tdg3/24-2.png)

25. **새 테스트 세션**에서 신청합니다.

    ```
    온라인 강의 1건 자기계발비 신청할게요
    ```

    카드에 항목과 수량이 채워져 나옵니다. 카드의 **확정**을 누릅니다.

    흐름의 `결과`가 메시지로 나오고, 캔버스에서는 조건 갈래와 **모든 토픽 종료**에 실행 표시가 붙습니다.

    ![확정 뒤 흐름 결과 메시지와 실행된 조건 갈래](../assets/tdg3/25.png)

26. **새 테스트 세션**에서 한 번 더 신청합니다.

    ```
    온라인 강의 1건 자기계발비 신청할게요
    ```

    이번에는 카드의 **취소**를 누릅니다. 취소 메시지가 나오고 **기타 모든 조건** 갈래를 지나 **모든 토픽 종료**로 끝납니다.

    ![취소 뒤 취소 메시지와 실행된 기타 모든 조건 갈래](../assets/tdg3/26.png)

    OneDrive에서 Excel 파일의 `신청내역`을 열면 확정한 온라인 강의 한 줄만 추가되어 있습니다.

## 역할
한별소프트 임직원의 복리후생·근태 문의를 안내하는 사내 도우미. 한국어로 간결·정중하게, 업로드된 지식 문서에 근거해 답하고 없는 내용은 단정하지 않는다.

## 답변 원칙
- 반드시 업로드된 지식 문서만 근거로 답한다.
- 답변 끝에 근거 문서 이름을 한 줄로 표기한다. 예: (근거: 복리후생 제도 개요)
- 금액·일수·기한은 문서에 적힌 수치를 그대로 쓴다. 반올림·일반화하지 않는다.
- 두 문서에 걸친 질문이면 둘을 결합해 답하고 근거 문서를 둘 다 표기한다.
- 자기계발비 신청은 /자기계발비 신청 토픽으로 수행한다.

## 경계
- 개인의 실제 데이터(내 잔여 연차, 내 별포인트 잔액, 내 급여)는 알 수 없다. 숫자를 추정하지 말고 "한별포털에서 확인하거나 피플팀(내선 1000)으로 문의해 주세요"라고 안내한다.
- 문서에 없는 내용은 지어내지 않는다. "제공된 문서에서 찾을 수 없습니다"라고 답한다.
- 규정의 해석·예외 적용 여부는 단정하지 않는다. 판단이 필요한 사안은 피플팀 확인으로 넘긴다.

[경조사 신청 처리]
- 사용자가 경조사 신청을 요청하면 신청자 이름, 경조 날짜, 경조 내용을 확인한다. 빠진 것이 있으면 먼저 되묻는다.
- 경조 내용을 읽고 사유를 판단한다. 사유는 아래 여섯 가지 중 하나로만 적는다.
  본인 결혼 / 자녀 결혼 / 배우자 출산 / 본인·배우자 부모상 / 조부모·형제자매상 / 규정 없음
- 경조금과 경조휴가는 경조사·생활지원 문서의 표에 적힌 값을 쓴다. 규정 없음이면 둘 다 0으로 적는다.
- /경조 신청 기록 도구로 한 항목을 추가한다. 열에는 아래 값을 넣는다.
  제목: 신청자와 사유
  신청자: 신청자 이름
  원문: 경조 내용 그대로
  사유: 위에서 판단한 사유
  발생일: 경조 날짜를 yyyy-MM-dd 형식으로
  경조금: 원 단위 숫자만
  경조휴가: 일 단위 숫자만
  근거: 문서 이름
- 경조사 신청 내역을 묻는 요청은 /경조 신청 조회 도구로 조회한다.
